KV Cache（Key-Value Cache）是大语言模型在生成文本时，用来**避免重复计算历史内容**的缓存机制。

Transformer 每生成一个新 token，都要通过注意力机制“回看”前面所有 token。每层注意力会为每个 token 算出：
* Key（K）：可被后续 token 匹配、检索的索引
* Value（V）：被检索后实际提供给后续 token 的信息

没有 KV Cache 时，生成第100个 token时，模型会把前面 99 个token 再完整计算一次 K 和 V；生成第 101 个又重算一遍。这样很慢。

有 KV Cache 时：
1. 首次处理提示词时，模型计算各层的 K，V，并存入缓存；
2. 生成下一个 token 时，只计算新 token 的 K 和 V
3. 新 token 的 Query（Q）直接与缓存中所有历史K做注意力计算，再用结果加权历史V。
4. 把新 token 的 K、V 追加到缓存，继续生成。

因此，它显著降低了逐 token 生成时的重复计算，使长回答和多轮对话更快。

| 概念       | 类比               |
| -------- | ---------------- |
| Key      | 每段历史信息的“索引标签”    |
| Value    | 这段历史信息实际携带的内容    |
| KV Cache | 已经读过并整理好的“可检索笔记” |
| Query    | 当前生成位置提出的问题      |

但它有一个重要成本：显存/内存占用会随上下文长度、层数和并发请求增长。所以服务端常会做 KV Cache 量化、分页管理、前缀缓存、淘汰策略等优化。

KV Cache 用更多显存换更快的推理速度。
