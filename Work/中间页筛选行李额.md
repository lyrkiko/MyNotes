#### 三、现有逻辑流程

1. Repricing 结果回来后刷新运卡的逻辑梳理
```
当 repricing 响应返回后，运卡的刷新分为两种模式：显示 Loading 刷新（有动画过渡）和静默刷新（直接替换数据）。决策入口在 handleMiddleResponse 中，核心处理在 updateRepricingResult 中.


响应返回 (type: normal/repricing/more/moreLite)
    │
    ▼
shouldTriggerMiddleRepricing?
    │
    ├─ false → 静默刷新（直接 updateTabValue）
    │
    └─ true → updateRepricingResult()
                │
                ├─ isRepricing? (normal已有+当前repricing / moreLite已有+当前more)
                │   │
                │   ├─ true + needRefresh → 【显示 Loading 刷新】
                │   │       1. 设置 repricingTipType = loading（骨架屏出现）
                │   │       2. setTimeout(repricingDuration) 后更新真实数据
                │   │       3. 设置 repricingTipType = upper/lower/same（骨架屏消失）
                │   │
                │   └─ true + !needRefresh → 静默刷新（updateTabValueDirectly）
                │
                └─ false + isHitMoreGradeLiteABTest → 静默刷新（updateTabValueDirectly）

```

2. repricing 



 1.展示条件：用需求方案的"最低价 + 严格比价胜出"逻辑，并补充实验组E、AB实验分组逻辑

2.数据源范围，使用 fareCardResult.economy 的数据，展示运卡逻辑在 `getCabinCardItem`，其中包含外露的运卡及折叠的运卡。

3.用户勾选后的运价重排，实现方案按照以下逻辑执行：
重排逻辑：三段式：① 严格比价胜出且符合筛选 ② 折叠区中符合筛选 ③ 不符合筛选的剩余运价；
折叠区处理：选中筛选后，折叠区命中的运价依然折叠展示，展示 MORE_PRICE 入口；
取消筛选恢复：	基于 normal/repricing 重新跑 handleFareCard 恢复原始 fold 结果；
多选逻辑：	AND 关系（全选 = 同时含托运和手提）

4.实现方案需要补充默认勾选逻辑
5.骨架屏触发条件采用实现方案，repricing先返回也展示骨架屏
6.实现方案的状态模型需要扩展为需求方案的完整结构
7.实现方案需要补充完整的 UI 渲染设计
8.行李判断口径：实现方案补充严格比价胜出判断逻辑，托运行李应使用 `FREE_CHECKED_BAGGAGE_STRICT` , 此标识表示全程有行李额
9.实现方案中 more/moreLite 返回触发 handleFareCard 后不会重新计算筛选项，显示阻止 more/moreLite 触发筛选项重算。

##### 五、实现总结

1. 本次改动为中间页新增“行李快筛”完整链路，覆盖初始化、点击筛选、列表重排、空态/未命中提示和 repricing 后结果重放。
2. 首次请求返回后，handleMiddleResponse -> initBaggageQuickFilter 根据实验分组、最低价行李信息和当前舱等候选运价，决定快筛项是否展示。
3. updateTabValue 新增 originDataSource / originMorePrice / originFilterPartitionIndex / originFlightPassPartitionIndex，用于保存默认 fold 后的原始展示态。
4. 用户点击快筛时，updateBaggageQuickFilterSelected 会同步更新勾选态，并调用 applyBaggageQuickFilterToTabState 直接重算目标 tab 的展示结果。
5. partitionFoldedFareCardsByBaggageFilter 负责将原始运价拆分为命中外露、命中折叠、未命中外露、未命中折叠，并生成 baggageFilterResultMeta。
6. 列表层通过 getBaggageQuickFilterExtraItems 插入空态、未命中标题和匹配后的分区提示，使快筛结果在 CabinList 中可视化落地。
7. 新增 BaggageFilterUnmatchedTitle 与 BaggageQuickFilterEmpty，用于表达“未命中原因”和“双选无结果”场景。
8. repricing / more 数据返回后，applyBaggageQuickFilterResult 会基于当前 selectedTypes 重新应用快筛，保证筛选态不会被新数据覆盖。
9. 本次按方案 1 调整了折叠区交互：快筛结果若仍保留 morePrice，则直接 morePriceVisible = true，跳过“向上滚动再展开”的步骤。
10. 整体目标是让行李快筛从“仅展示筛选项”升级为“真实驱动列表结构变化”，同时保留现有 morePrice 数据模型与大部分渲染链路。
